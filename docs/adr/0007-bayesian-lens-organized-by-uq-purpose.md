# Organize the Bayesian Lens around named UQ purposes, bringing Calibration into scope

The Bayesian Lens previously held two fixed pieces of content — OOD distance and an optional epistemic/aleatoric decomposition — with Calibration explicitly left "open/deferred, not yet decided in or out" in CONTEXT.md. We restructured the Lens around four of the six distinct purposes uncertainty quantification can serve (Error detection, Calibration, Distribution-shift detection, Simulation reliability — see UQ Purpose in CONTEXT.md), recorded per Model rather than assumed as one blanket "has UQ" claim, and brought Calibration into scope as one of them. The other two purposes from the underlying framework (Active learning, Model comparison) are named in a reference table on the Lens but not built out as Hub content.

**Why:** a single "has UQ" badge hides that calibration, error-ranking, distribution-shift sensitivity, and simulation-level reliability are different claims that can each hold or fail independently — a model can be well-calibrated and still rank errors poorly, or OOD-sensitive while still confidently wrong near the boundary. Recording which purposes have actually been evaluated per Model, rather than one checkbox, is closer to the Hub's core pitch ("show what the uncertainty has been demonstrated to be useful for, under which conditions") than the two-field version it replaces. We prioritized these four purposes for the initial demo over the full six because they have a direct, reproducible evaluation (coverage checks, error-uncertainty ranking, OOD distance, trajectory monitoring) achievable from precomputed example data; Active learning and Model comparison each need either a labeling loop or a second catalogued Model under identical conditions, neither of which the Hub has.

**Considered options:** build all six purposes out as full Hub content — rejected for now, it commits the Hub to ongoing content for Active learning and Model comparison without a labeling pipeline or a same-conditions second Model to compare against; worth revisiting once more Models are catalogued. Leave the Lens as a framework-only overlay (explain the six purposes, relabel the existing two charts, add nothing new) — rejected, it would leave Calibration still unevaluated and undersell the Lens's actual differentiator by skipping the error-detection and calibration evidence the framework itself prioritizes for an initial demonstration. Add a "purpose" tag to the Bayesian Annotation (community note) form, mirroring the framework's "record purpose as a first-class property of each study" — rejected for this pass; the curated/precomputed content is now organized by purpose, but the Community Annotation schema stays free-text to avoid changing an already-settled subtype in the same pass.
